Scribeberry

A capable documentation tool with solid EHR connectivity and note generation, but three critical findings tied to cross-platform session failures and a broken UI state place meaningful constraints on safe deployment in multi-device clinical environments.

Evaluated using our independent human factors framework. Vendor-free.

C 73.6 / 100
Overall Score
Executive Summary

What You Need to Know

Scribeberry is an ambient AI scribe designed for outpatient clinical settings, combining voice-captured documentation with note generation and EHR export tools. The tool earned an overall grade of C (73.6/100), reflecting adequate performance across core documentation features alongside a meaningful concentration of violations in system transparency and clinical note integrity.

Scribeberry's strongest qualities lie in its note generation workflow and EHR connectivity. The tool supports generated notes, post-generation editing, SOAP formatting, custom templates, speaker attribution, and direct EHR integration with a widget layer. Security and compliance documentation is solid, with SOC 2 Type 2, HIPAA compliance, and trust documentation all publicly listed. The tool also covers all major device types and most clinical settings, and supports multiple languages with specialty-level configuration.

The most significant concerns center on Match Between System and the Real World and Visibility of System Status — specifically how the tool handles cross-platform session management. Three critical findings were identified, all tied to scenarios where the system's behavior sharply diverged from what a clinician would reasonably expect: duplicate notes generated silently across devices, and a UI state in which a core control becomes physically unreachable. Organizations considering Scribeberry should carefully evaluate their cross-device workflows and documentation verification practices before deployment, particularly in settings where multiple devices are in routine use.

Cross-Platform Generation Creates Duplicate Clinical Notes

When a dictation is started on desktop and a note is generated on mobile before the desktop completes, the system fails to reconcile session states across platforms. Both devices independently produce a note, creating two conflicting versions in a single patient record. Neither platform communicates that the other has already generated output, leaving the provider with no way to detect or prevent the duplication before it becomes a permanent entry — a workflow burden and compliance risk with no system-level safeguard.

Critical — Severity 4

H2 Real World Match  ·  H1 System Status  ·  H8 Aesthetics

Mobile Note Fails to Sync to Desktop, Triggering Silent Duplication

A note generated on mobile does not appear on the desktop — even after a manual page refresh. If the provider then generates on desktop, a second note is silently created with no conflict warning, no prompt to resolve the state, and no indication that duplication has occurred. Two competing clinical notes now exist in the same record, introducing confusion at care review, billing complications, and regulatory risk without any system-level alert to the user.

Critical — Severity 4

H3 User Control  ·  H9 Error Recovery  ·  H5 Error Prevention

Task List Growth Traps the Save Control With No Recoverable Exit

When AI-extracted tasks are added, the Task List panel grows without a scroll boundary, expanding until it covers both the Save button and the panel's own toggle. Once obscured, the only exit is destructive — the provider must delete tasks to re-expose the save control. A routine AI feature can trap the user in an unrecoverable state with no clearly marked exit, potentially causing unsaved notes and permanent loss of clinical documentation.
